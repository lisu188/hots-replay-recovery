# Bounded installed-CASC metadata observation

The actual installed `2.57.0.98348` storage was opened through the unchanged managed CascLib DLL embedded in Heroes.XmlData 1.1.1. No SDK, full HDP installation or game process was used. The package was inspected in RAM and its SHA512 matched NuGet's official catalog. Only `lib/net10.0/CascLib.dll` (277,504 bytes), its license and provenance were saved. Actual assembly loading under PowerShell 7.6.5/.NET 10.0.11 confirmed BCL-only assembly references.

The source reviewed is Heroes.XmlData commit `1cfc5150320079c79cb7d618778ef5afcb11a3fc`, including its CascLib submodule `205154e3c269d5e2a7c099e5bb77050185599d21`. `primary-source-guard-provenance.json` records exact Git blob identities, URLs and relevant lines.

Two original API behaviors require explicit controls. `LoadLocalStorageConfig` opens its three configuration inputs with the default ReadWrite access, so the loader parsed small byte-identical copies under taskwork. Only afterward was its in-memory BasePath changed to the installed root, whose index/data streams use explicit read-only access. `OpenFile` can call the online reader even when the fallback flag is false. A custom HttpMessageHandler therefore rejects every request before transport; a canary verified rejection, and both actual store operations recorded zero HTTP attempts. Cache writing was disabled, LoadFlags was None, and working directory, log and temporary paths were task-local. Installed configuration hashes remained unchanged.

The filename-only path examined all 1,208,637 names in the decoded MNDX database with an explicit 1.5-million cap. It did not create the full asset tree. The original broad build/package token filter found 430 paths, including 106 asset filenames containing `Build`. A complete, untruncated filtering pass retained 324 exact metadata filenames: 108 each of DocumentHeader, DocumentInfo and ComponentList.StormComponents. No filename ended in `.s2mh`. This proves the stated filename observation, not absence of equivalent unnamed or embedded content.

Only the three identified files under `mods/heroesmapmods/battlegroundmapmods/dragonshire.stormmod/` were subsequently read. Selective lookup invoked the unchanged private MNDX lookup routines after initializing their package-name tables with original enumerated values. Each output was capped at 2 MiB before and during reading, its complete content MD5 matched its CASC CKey, and the entire decoded root's content MD5 independently matched `c3b3c8bc82e3a5a62e550fdde9a40c28`. The three private metadata outputs total 2,311 bytes. They differ byte for byte from their namesakes in the cached `f557190f...s2ma` map archive; the local module and that map archive have distinct dependency roles. None is an exact recovered current US `.s2mh` object.

The library's `Clear()` threw NullReferenceException in this partial internal filename path, which intentionally omitted storage-tree initialization. Reports retain this cleanup result separately. Source order disposes mapped data and index state before the null tree access, and each short-lived process exited. This observation makes no claim that the library's normal complete public workflow fails, nor that the full parser or game accepts a migrated replay.

The first open stopped at a conservative one-million-name preflight cap; its cleanup exception masked that bound failure in the tool output. The measured root count justified the explicit 1.5-million cap used by the completed scan. Neither failure was bypassed by downloading data or changing installed storage. Earlier scratch reports remain historical; use `local-casc-strict-metadata-filenames.json` and `casc-current-dragon-cache-crosscheck-v2.json` for narrowed interpretation.

No raw game metadata should be published from this directory. The publishable evidence consists of allowlisted paths, sizes, digests, package/source provenance and operation outcomes. The three binary members and software DLL remain task-local. `enumerate_local_casc.ps1` is a bounded research helper; its normal and `-ReadDragonMetadata` modes reject existing output/log/member filenames and are intended for a fresh task directory containing the validated DLL and staged configuration copies.

The executed helpers are frozen research sources, not a portable supported CLI. The PowerShell reader assumes the standard Windows installation path, uses its own directory for all task state, and expects `config-copy` produced by the staging helper. The staging Python source imports the existing bounded reader from this machine's recorded repository path and writes beside itself. These assumptions are retained so the source hash describes the code actually executed. Reproduction requires an equivalent isolated setup; changing paths produces a new wrapper whose execution must be recorded separately. No untested portable rewrite is presented as the producer of these observations.

Inspection of the three saved members found one explicit dependency referral: `bnet:Heroes of the Storm (Data Mod)/0.0/999,file:Mods/HeroesData.StormMod`. It gives a catalog ID and textual version for a dependency, with no region or exact header hash. The DocumentInfo contains no self-published catalog ID. No direct US/EU `s2mh` handle, raw/hex representation of the six known current US header digests, or HTTP URL was found in these three bytestrings. The local binary DocumentHeader has a different outer container from the self-describing depot mapheader; its following fields were not assigned guessed semantics. This establishes no new route to the three missing exact US headers. See `dragon-metadata-chain-observation.json`.
