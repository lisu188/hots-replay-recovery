## Verified representation defect

The migration had preserved packed unit references numerically. Their observed layout differs between the source and real modern recordings:

- Original/R5 references match tracker identity pairs with `(index << 18) | recycle`.
- The genuine 98285 Braxis reference has 6207 non-sentinel references spanning 562 distinct tags. Testing shifts 1 through 31 joins every reference to its tracker identity only at shift 22.
- The genuine 98285 Dragon reference supplies one usable selection reference and is compatible with shifts 22 and 23 on its own. The pooled evidence from both recordings identifies shift 22 uniquely.
- All 15305 non-sentinel R5 references match its preserved tracker identities at shift 18. Of these, 15301 encoded values change when repacked to shift 22; four index-zero values do not change.

This is an inference from concrete game-event/tracker relationships, not a claim that Blizzard published a complete 98285 schema. In particular, the older pinned schema's `unit_tag` helper still describes the older layout.

Example: the first affected selection at loop 52 references index 173, recycle counter 1. Its packed value changes from 45350913 to 725614593. No different unit instance is selected by the transformation's intent: the two components are preserved. Whether index 173 denotes the intended unit in the new live simulation is a separate, unproven question.

The old and fresh Dragon recordings also do not have identical initial tracker object sets: their first hero spawn indices differ. A universal index offset cannot be inferred from different matches with different rosters and rules. Numeric ability identifiers, command-flag meanings, dynamic unit allocation and original simulation behavior need independent reconciliation. R6 fixes packed representation only; the original synchronization values can still reject the new simulation at its first check.

Further work should identify the actual initial live state/catalog differences, or reproduce the original rules and object allocation, while preserving the original record. Copying another match's synchronization values or disabling the error would not establish faithful recovery.
