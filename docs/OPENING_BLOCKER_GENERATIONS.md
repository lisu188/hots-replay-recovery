# Gate removals and subsequent unit generations

TEN removes 30 normal and 24 diagonal pathing blockers at the single GatesOpen statistic, loop 610. Build 98348 GameLib lines 16360–16373 enumerate the two unit types in that order and call UnitRemove. The map supplies each authored index, integer coordinates and opening generation. The source tracker supplies the order within each type. Four historical Dragon Shire recordings share the same removal order. Each of the fifteen stock recordings has a different within-type order, so the old chronological order is retained as an explicit input to the historical projection.

The source records have an absent killer player. The target records encode player 0, with both optional killer unit fields absent. This holds on all 216 historical and 810 current removals. Re-encoding the 810 target frames at their original positions reproduces 27,525 bytes. TEN's 54 target-format removal events form a 1,836-byte sparse stream, SHA-256 `b5d20bbe65a5b09b83f2ec0822a96541809a8b2b7e7068d47dcfe13409f83a94`. The separately generated stream retains source order and uses sparse timing deltas. [Gate removal evidence](../observations/blocker-deaths.json)

All 42 opening wave units in each historical match reuse indices of the 54 removed blockers. All fifteen current recordings reuse 36 such indices and use six other indices. Fourteen current recordings place the first six wave units in consecutive indices after the previous tracker maximum. Twelve also assign generation one to all six. Even with identical historical removal order, the four historical wave tag sequences are different. The records do not determine the free-list ordering or a seed-to-slot rule.

Across the whole TEN tracker, 15,885 positive generation numbers below the last observed value of their respective slot are absent from all unit births and initializations. The first gap appears at loop 849 on slot 95, whose blocker had generation 1 and whose later beetle has generation 5. This counts holes in observed numbers. Equating each hole with exactly one native allocation requires a separate proof of the engine's generation update. Command targets and updates, optional command units, selection additions and explicit ping tags all refer to generations whose birth was already observed in all 19 recordings. These inputs cannot supply the missing sequence.

Of the six distinct post-opening generations referenced by TEN's nine remaining pings, the second Dragon Knight skips one number since the preceding recorded allocation of its slot. The fourth Dragon Knight skips none. The ranged minion, footman, Monstrosity and mercenary knight skip three, four, six and 31 respectively. Selecting a target slot and predicting its next generation remain separate requirements. [Per-recording counts and ping evidence](../observations/unit-generation-evidence.json)
