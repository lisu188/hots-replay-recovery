# Native current command-flag transport and selected target gate

The installed98348 binary now provides a concrete command-validation route for
the flag investigation. One selected construction path copies the internal
command's32-bit flags into the serializable event without a shift/mask. A separate
consumer checks the exact command-event header before calling a validator that
reads those same flags and later branches on bit18. A portable model of one
114-byte post-callback block matches bounded interpretation of its actual
instruction bytes across128 finite input combinations.

This is conditional current-code evidence. It does not recover historical41810
flag names or the live ability callback results and does not authorize a new
flag mapping. The existing conversion and original/R8 replay bytes are unchanged.
The latest human instruction, **Keep all work offline**, still applies.

The read-only probe covers original41810, R8 and the already preserved current

All16 original commands left at flags `0x80100` have an explicit ability,
target choice `None`, command index0, and no `otherUnit`/`unitGroup` override.
Nine reference source ability link126 and seven link351. Their first recorded
loop is1682, last18663. These are numeric historical links, not authenticated
current catalog names or proof of the executed caster. They are later than the
64-loop analysis window, which itself is not a measured first divergent tick.

R8 contains622 commands at flags `0x80100`, all explicit/None. The current
control contains531, also explicit/None. None of the three inspected streams
contains `0x40100`. Absence in these recordings does not prove a native bit's
meaning or a general prohibition.

## Selected post-callback block

`native_command_target_gate.selected_target_gate` models only
`[202B475,202B4E7)`, SHA-256
`0628f11ab41f48f87c1096703d2cf46528d3ae4fdfdefdc1c352bae741a809c6`.
Its true continuation is `202B4E7`, false/cleanup continuation `202B3C4`.
It assumes this block has already been reached under normal ABI and valid
object/callback conditions; earlier checks can exclude combinations modeled
here. It is not a whole-command acceptance API.

Inputs are current target tag0..3, flags bits18/23, callback class0..3 and an
uninterpreted native context bit2 from `DWORD[frame_RBP-0x11]`. The model rejects
other class values rather than inventing their meaning. Callback classes are
not assigned ability names. The selected formulas are:

| Callback class | This block reaches its true continuation when |
| ---: | --- |
| 0 | Target is neither Point nor Unit, bit18 clear and bit23 clear |
| 1 | Target is Unit or bit18 set |
| 2 | Context bit2 set, target Point or bit18 set |
| 3 | Target Point/Unit or bit18 set |

For the16-command shape (`None` target), bit23 clear and context bit2 clear,
the two flag values produce:

| Flags | Class0 | Class1 | Class2 | Class3 |
| --- | --- | --- | --- | --- |
| Existing `0x80100` | true | false | false | false |
| Unapplied hypothesis `0x40100` | false | true | true | true |

Context bit2 can change the class2 result. Bit19 is not read in this selected
block; that does not make it irrelevant elsewhere in the validator or engine.
These conditional differences show why moving the16 cases mechanically to
`0x40100` is not justified by equal wire shape. Which path is correct depends
on authenticated historical semantics and the relevant ability/catalog callback
state, none of which is recovered by a replay flag histogram.

## Validation and unchanged requirements

A small opcode interpreter evaluates the36 selected instructions using their
actual pinned bytes, unsigned comparison flags, relative branches and explicit
input state. All128 combinations across the bounded input domain agree with the
portable formulas. This is finite static instruction interpretation, not native
execution, CPU/emulator integration, arbitrary-callback execution or gameplay.

Six new focused unit tests cover the class table, context dependency, target
classes, bit23, bit19's absence from this block and invalid inputs. Neighboring
game codec/fidelity tests remain separate local checks. Root test discovery will
include the new module; no hosted CI, broad local corpus or peer review is claimed.

No replay or synchronization value was changed, no game/Computer Use/network
operation occurred, and nothing was published remotely. Original/R8/control
hashes remain unchanged. Full upgrade, old/current ability identity, missing
lobby/player/catalog state and deterministic playback remain unproved. The next
semantic dependency is the actual historical/current callback/catalog meaning,
not another unvalidated flag rewrite or a checksum transplant.
