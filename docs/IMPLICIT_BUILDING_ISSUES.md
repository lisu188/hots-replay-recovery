# TEN building-target commands

The offline projection emits 39 of TEN’s 740 implicit unit-target issue commands. The 1,189-byte sparse stream has SHA-256 `52b95d077d249384651c8ffe54881a7085b78ab077360b4af836ae357339cb0f`. Source ordinals retain their original zero-based numbering. The targets are nine cores, five gates, seven healing fountains and eighteen forts or keeps.

The GateOrder map’s ordered placements and startup allocator provide the target tag and initial owners. The original command selects the intended object. The scan requires agreement on authored X/Y, an active initial generation and an ownership history consistent with both initial owners. The package terrain supplies Z. For forts and keeps, town initialization statistics independently identify all twelve map locations by TownID. Destruction statistics reproduce all six corresponding source unit-death loops. The replay lacks an independent second death record for the other building types in this projection.

Every included source issue carries flag `0x100108`, a mandatory sequence, and absent ability, other unit and unit group. The candidate carries the recorded user, tick and issue sequence, sets flag `0x80108`, omits the vector and generates a new target snapshot. The numeric catalog link for each type is qualified by the stock Dragon Shire catalog observations and both external recordings. The candidate still assumes the custom package resolves those numeric links identically, the relevant buildings survive as recorded, and the original sequence identifies the corresponding target command-manager session.

Across 15 original build-98348 Dragon Shire recordings, generated snapshots and complete native issue frames match 6,523 physical records totaling 195,690 bytes. The fifteenth match was excluded from the earlier link qualification. It supplies 336 independently reproduced frames, including examples of all seven TEN unit types. The physical control preserves the enclosing record’s original delta. Sparse output uses deltas between admitted rows. Across these controls, town statistics also reproduce 84 town-hall deaths and cover 3,026 issues.

The separate selection check replays the accepted historical selection deltas and compares the owner/player binding and primary hero’s independent life history at issue time. At source ordinals 51187, 102795 and 102952, the most recent accepted selection contains a single continuously living owned hero. In 29 cases a hero lifetime boundary intervenes. Seven have an unresolved earlier selection. Target execution and the complete stream remain unverified.

`implicit_building_issues.generate(source, gate_map, mechanics, catalog_path)` returns the projected events by ordinal, the sparse bytes, and the source receipt. The CLI accepts `--native-controls` with replay digests and paths, `--stock-map` for the 98348 Dragon Shire map, and `--private-output` for a new file. `building_issue_selection.py` takes the same positional inputs followed by the historical hero timer curve and the physical selection-controls observation.
