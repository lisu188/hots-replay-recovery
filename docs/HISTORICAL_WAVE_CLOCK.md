# Dragon Shire lane wave timing

In TEN all ten players receive the gates-open upgrade on loop 610 and the minion-spawning upgrade on loop 690. The first six footmen appear on loop 691. In all four original-build recordings the two upgrades are 80 loops apart. In fifteen build-98348 recordings they are one loop apart. Both builds emit the first footmen one loop after the minion-spawning upgrade. The historical wave period is 481 loops and the stock period is 480. Across these samples the resulting timetable accounts for 6,804 historical and 24,150 stock footman, wizard and ranged births by loop, type, control and upkeep. [Recording checks](../observations/gate-upgrades-and-wave-births.json)

The map registers a delayed handler on the existing wave-start timer before map initialization dispatches the game libraries' gameplay callbacks. It disables the original registration, adds a 79-loop wait to the actionable invocation, sets the interval to 30.0625 game seconds and calls the original handler with its original flags. That handler applies the upgrades and starts the minion system. Delaying only the first visible unit would leave the upgrade and system activation 79 loops early. Map code still uses the ordinary team, lane, formation and stop controls. Catapult eligibility has its own gameplay rule.

Compared with the respawn map, only MapScript.galaxy changed. Two builds gave identical bytes. A separate harness extracted the installed stock callback and the new callback from the finished map and exercised 16 combinations of condition, action, AI and spawning flags. The harness models game time in ticks. Execution of the Galaxy scheduler on the modified map and its simulation checksum remain unverified.
