# Exact legacy-name XML node scanner

`scan_collection_alias_nodes.py` depends only on the Python standard library and the repository's reviewed `collection_license_audit.py` and `plan_collection_candidates.py`. The CLI is intended for a fresh HeroesDataParser 5.1.0 extraction of live version 2.57.0.98348.

```powershell
python -B scan_collection_alias_nodes.py --root extracted --projection observations/collection-license-current-98348.json --collection-observation observations/collection-identities-2026-10-18.json --version-log heroes-version.log --output new-alias-node-observation.json
```

The CLI requires the exact published projection SHA-256 `c8f03ddbc859feb5c2dc1836761201b5e6fea4632ce0325817abdd7299c8aa22`. It recomputes the planner's 207 unresolved names from the 263 legacy names and 5,418 observed current collection IDs. It checks every one of the 5,575 projected XML paths, byte sizes, hashes and parser metrics. Extra or missing XML is rejected. The fresh version log must name only 2.57.0.98348. Every projected `hdp.info` path must exist with the named `Version` field equal to that version and `IsPtr` strictly false. Fresh extraction timestamps can change metadata bytes, so their new hashes are reported instead of requiring the original metadata hash.

Matches are whole, case-sensitive attribute, element-text or tail-text values. Substrings, values embedded in paths, and trimmed or case-folded variants are excluded. Each match has an XML-relative source path, owning catalog kind/ID, namespace-preserving node path with child ordinals, matched attribute or text location, matched value and a conservative role. A visual reference or catalog record identity is not a registered legacy reward alias.

Selected `License`, `RequiredRewardArray`, `AttributeId`, `DisplayModel` and `VariationArray` fields are included only for the same matched `CSkin`, `CMount` or `CReward*` owner. Unsupported attributes, nested content, array operations, templates and removal operations remain unresolved. No inheritance, cross-record join, catalog order, ownership or entitlement conversion is performed. The scanner exports no raw XML, unmatched arbitrary attribute values, player data or absolute local paths.

Four fixed unit queries are separate from the collection-name scope: `NovaHoloCloneCloaked`, `NovaHoloClone`, `AbathurEvolvedMonstrosity` and `TownCannonTowerL2Standalone`. Only direct `Catalog/CUnit` declarations with an exact ID match qualify. Their source path/digest, parent/default and bounded direct `BehaviorArray`/`UnitAlias` scalar attributes are projected without inheritance or alias interpretation. Unit absence is reported only for a complete verified XML inventory; subset absence fields are null. No numeric unit link or replacement is inferred.

The existing collector supplies bounded tree traversal, no symlink/reparse/special-file input, XML byte/depth/element/aggregate limits and DTD/entity refusal. Further limits bound matches, selected related and unit fields/declarations, node-path length and JSON size; exceeding a limit fails the scan instead of truncating its result. The output must be new, have an existing directory parent and be outside the extracted input tree. Input files are read only. There is no all-or-nothing filesystem transaction claim.

`scan_subset()` is a separate research helper; it always reports incomplete coverage, even if the supplied subset happened to contain every expected path. `verify_alias_scan_public_subset.py` checks the nineteen already retrieved genuine public snippets against both their retrieval provenance and the exact current projection. That subset has thirteen exact matches: eight visual references for two names and five existing reward record identities without a direct observed license candidate. It proves no alias and no complete absence result. Only a successful full CLI scan of the fresh remote extraction can establish the full inventory scope.

`test_scan_collection_alias_nodes.py` has 30 synthetic tests covering exact matching, text tails and record-owner boundaries, namespace locations, conservative related fields, fixed direct unit queries and their bounds/absence scope, privacy, metadata/log/projection provenance, complete versus subset scope, missing or changed XML, malformed XML and DTDs, bounds and output preflight. Synthetic fixtures are labeled and do not establish actual build compatibility.
