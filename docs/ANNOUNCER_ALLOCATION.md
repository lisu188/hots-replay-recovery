# Allocations during the opening announcement

The signed Dragon Shire map selects the stock announcer default. Its target SoundLib calls SoundPlayForPlayer with SoundLink as its first argument. In the successful ordinary path, the expression requires two allocations in the same Galaxy registry. SoundLink first creates a class-16 object and stores the resolved sound descriptor in that object. SoundPlayForPlayer requires a live class-16 input. It obtains a separate class-15 sound whose handle is written into event 46. The sound catalog name and the soundlink handle cannot supply the class-15 handle.

In 98348, the SoundLink VM entry (1236) calls 0x20d37f0. The successful resolver calls the shared allocator at 0x20d3b34 and returns the object's handle from offset 8. Its vtable class method returns 16. The SoundPlayForPlayer VM entry (1238) checks class 16 at 0x20d6121 and calls the same allocator for the sound at 0x20d62dc. Before its creation attempt, it clears the current context's last-played reference. When the old nonreserved slot loses its last reference this can retire the object and prepend its slot to the free list. Successful creation stores the new sound's handle as last played; SoundLastPlayed (1242) reads the same field. These operations depend on live prior state.

The map's ordinary announcement group is players 0–10. PlayerGroupNextPlayer (1142) scans its class-11 group's mask forward from the previous index plus one, through bit 15. Starting at -1 therefore visits observer 0 first. This fixes script visitation order. Queued or skipped sounds and other native activities can still change allocation or reporting order. The association between replay reports and this particular announcer remains conditional.

Nineteen archives qualify. Every common word in these 19 archives has generation greater than one, ranging from 3 to 162, and therefore uses a previously allocated slot under ordinary allocation.

The minimum-allocation calculation does not require the no-wrap assumption.
