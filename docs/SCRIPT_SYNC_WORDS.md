# Dragon Shire’s hero leader panel and Galaxy script checksum

**The full primary builder writes `0x99f8b879` to slot 68 on clean Dragon Shire startup with the identified packages.** The native dispatch table maps Galaxy ID 776 to `SetHeroLeaderPanelEnabled`. The primary builder hashes the little-endian DWORD storing this setting. The file-backed PE initial value and both native reset leaves are 1. The script setter can assign 0 or 1 and a separate stream reader can restore the saved scalar.

The original TEN archive names the historical Dragon map. Two independent build-98348 replays name the current Dragon map. Each map includes 22 distinct Galaxy library files transitively. Across those closures, the only external use of the tutorial cinematic helper passes `false`, whose branch can keep or enable the panel. Its disabling branch needs `true`. A read-only content-key-validated scan of 215 named installed mod scripts found additional references in tutorial and brawl packages. Neither Dragon archive declares those dependencies. The historical map root and current map root reference neither the setter nor the cinematic helper. This bounds the opening prediction to a fresh game using the identified scripts. A restore, a different loaded package or a dynamically supplied script can change the setting.

The actual GateOrder overlay has whole-archive SHA-256 `bda7aafd1d63c77b3b4d29ff2afee96da09a3104b54b4a1d625bb299607d9008`. Its modified 55,616-byte root script contains zero references to the setter or tutorial helpers. Its dependency declaration, 22 transitive script names and all their SHA-256 hashes match historical Dragon with the identified 98348 libraries. Its full primary builder likewise produces `0x99f8b879`. The fast mode-4 builder clears this slot to zero. The published value depends on the history entry selected at the actual sample.

**Slot 46 hashes the native global named `ScriptChecksum`.** When the loader at RVA `0x1ff2f03` accepts a nonempty script buffer it computes the ordinary CRC-32 of its bytes, then extends its running checksum with the four little-endian bytes of that CRC. Empty buffers leave the checksum unchanged. The primary builder at RVA `0x970b80` hashes the resulting cumulative DWORD again. The historical Dragon root script has CRC-32 `0x9a388594` and the current control root script has `0xb69266c3`. Each was read directly from the map archive referenced by the respective physical replay. Resolving the final TEN value requires the ordered buffers seen by the loader, including the hero package scripts. Source-level include order alone does not establish that sequence.

GateOrder’s root script CRC-32 is `0x3c880bd6`. The loader contribution from this member depends on its input buffer and its position among the other loaded scripts. Fast mode 4 clears slot 46 to zero. The full-builder value remains unresolved for GateOrder.

Run `verify_script_sync_words.py EXE TEXT INSTALLED_SCRIPT_DIR PACKAGE_SCAN SOURCE_REPLAY SOURCE_MAP CONTROL_MAP --gate-order-map GATE_ORDER_MAP --control REPLAY_A --control REPLAY_B`. The project’s standard Python path supplies the MPQ reader and pinned native vector verifier. Supply the original Galaxy extraction manifest as `INSTALLED_SCRIPT_DIR/member.json` (SHA-256 `87b44ff3f91d9058f5001f926129a04d225f8a11fa05b99e1571362539ec3b7b`) and the caller-scan JSON as `PACKAGE_SCAN` (SHA-256 `563059862406f74ce8ff04d340232d694e710f0258beb4e70abd2ed5f1ced6d6`). The verifier authenticates both manifests and the extracted scripts. The sampled control replays omit the primary vector, so the verification uses their physical map references.
